Render.com Outage Diagnostics

Post-Mortem & Incident Analysis

● Resolution: Deployed

1. Incident Overview

This section summarizes the core issue. Users on Mac browsers (Chrome/Safari) experienced a complete inability to reach dashboard.render.com or Render-hosted applications, resulting in an ERR_CONNECTION_REFUSED error. The anomaly was that native iPhone browsers on the same cellular network worked perfectly, and standard TCP VPNs failed to resolve the block.

Primary Symptom

ERR_CONNECTION_REFUSED

Affected Devices

Tethered Laptops (Mac)

Root Cause

Carrier DPI & SNI Sniffing

Implemented Fix

WireGuard UDP Tunnel

2. The "Smoking Gun" Anomaly

This chart visualizes the critical diagnostic data point from the terminal curl -vI test. By comparing expected local rejection times against the actual 149ms delay, we proved the connection was leaving the machine and being intercepted at an intercontinental routing node, completely ruling out local Mac firewalls.

Insight: A local /etc/hosts or packet filter rejects in <10ms. A 149ms latency perfectly matches the physical round-trip time from East Africa to US/EU nodes.

3. Impact on UB Ecosystems

This visualization illustrates the friction point within User Behavior (UB) models. When deployments are consumer-facing, this specific carrier block acts as a silent funnel leak for tethered users. This drop-off registers as an error in SGD models, manifesting as silent abandonment in the UI/UX layer.
